# Универсальный MCP-коннектор к базам 1С

**План разработки · Разработчик: Стас Чашин, Stas@Chashin.pro · сентябрь 2026**

Один адаптер, который открывает любую конфигурацию 1С — типовую или самописную — для ИИ-агентов и внешних приложений по MCP и REST: чтение, запись, отчёты и вызов бизнес-логики под контролем прав и аудита.

| | |
|---|---|
| **Статус** | Тиражируемый продукт |
| **Архитектура** | Расширение `.cfe` + внешний шлюз |
| **До релиз-кандидата** | ~18–21 неделя |
| **Команда** | 4,5 FTE |
| **Правовой режим** | Clean room |

## 01 · Правовая рамка: разработка с нуля

Это первое инженерное решение, а не юридическая формальность. Чужое расширение под задачу конкретного вендора несёт чужие компромиссы; универсальному коннектору нужна другая модель безопасности, другая интроспекция и другой контракт API. Переписывание чужого кода не даст ни одного из этих свойств — только риск.

**Режим работы команды:**

- Источники — только официальная документация 1С и ИТС по HTTP-сервисам, публикации на веб-сервере и механизмам расширений конфигурации. Декомпиляция и анализ сторонних `.cfe` исключены регламентом; разработчики не получают к ним доступ.
- Собственные имена и префиксы объектов метаданных, собственные UUID, собственная структура API. Никакого совпадения имён общих модулей, HTTP-сервисов, ролей и справочников с чужими продуктами.
- Происхождение кода фиксируется: git с подписанными коммитами, ADR-записи на каждое архитектурное решение, чек-лист приёмки. При спорной ситуации это доказательная база.

Публичные факты об интерфейсе — что подключение идёт через публикацию на веб-сервере, что нужны роль и права, что вызовы приходят в HTTP-сервис — это описание платформенных механизмов 1С, общих для всех. Их использование ни у кого не спрашивают.

## 02 · Архитектура: три слоя

Тонкий слой в 1С, вся сложность протоколов — снаружи. MCP развивается быстрее, чем выходят релизы 1С; держать JSON-RPC, SSE и OAuth внутри конфигурации значит обновлять расширение у клиентов на каждое движение спецификации.

### Слой A — Адаптер конфигурации (`.cfe`, внутри 1С)

Один HTTP-сервис с версионированной маршрутизацией, ядро сериализации типов 1С в JSON, интроспекция метаданных, whitelist доступа и журнал. Заимствований типовых объектов — минимум, чтобы не мешать обновлениям конфигурации.

Точки входа: `/v1/meta` · `/v1/data` · `/v1/query` · `/v1/report` · `/v1/action` · `/v1/job`

↕ *HTTPS · JSON · mTLS или VPN*

### Слой B — Протокольный шлюз (Python / FastAPI, снаружи)

Собирает набор MCP-инструментов из метаданных конкретной базы, отдаёт OpenAPI 3.1 для агентов без MCP, держит кэш метаданных, аутентификацию, лимиты и трассировку. Один шлюз обслуживает несколько баз с маршрутизацией по тенанту.

MCP stdio + streamable HTTP · REST / OpenAPI 3.1 · кэш метаданных · лимиты · маршрутизация тенантов · OpenTelemetry

OAuth2 client credentials на шлюзе отложен (ADR-0010).

↕ *MCP · REST*

### Слой C — Агенты и приложения

Всё, что умеет MCP или HTTP-API. Специальных доработок на стороне потребителя не требуется — это и есть смысл «универсального» в названии.

Claude / Claude Code · PIX Operator · n8n · Dify · GigaChat · YandexGPT · внутренние сервисы

### Состав расширения

Объекты метаданных подобраны так, чтобы настройка коннектора была работой консультанта, а не программиста: доступ, запросы и разрешённые действия описываются данными, а не кодом.

| Объект | Тип | Назначение |
|---|---|---|
| Маршрутизатор, Сериализация, Интроспекция | Общие модули | Разбор запроса и версия API, конвертация типов 1С ↔ JSON (ссылки, даты, табличные части, хранилища), обход дерева метаданных в JSON Schema |
| Безопасность, Данные, Запросы, Отчёты, Действия | Общие модули | Проверка скоупов, CRUD и проведение, валидация запросов, исполнение СКД, вызов разрешённых процедур |
| КлиентыИнтеграции | Справочник | Приложения и агенты: хеш токена, скоупы, сопоставленный пользователь 1С для RLS и аудита |
| ПравилаДоступа | Регистр сведений | Матрица «объект × операция × поля»: что клиенту вообще видно |
| ИменованныеЗапросы | Справочник | Готовые запросы с параметрами и схемой результата — безопасная альтернатива произвольному тексту запроса |
| ДействияИнтеграции | Справочник | Whitelist экспортных методов конфигурации: сигнатура и описание на естественном языке для агента |
| СемантическийСловарь | Регистр сведений | Человеческие названия, синонимы и примеры для объектов и реквизитов — то, что делает ответы агента точными |
| ЖурналВызовов | Регистр сведений | Кто, что, когда, сколько длилось, что создал — с ссылками на объекты для разбора и отката |
| АдминистрированиеКоннектора | Обработка | Настройка, генерация токенов (без DRM продукта), мастер-чеклист публикации, самодиагностика |
| ДоступКоннектора | Роль | Минимально необходимые права, отдельные от прав живых пользователей |

## 03 · Чем этот продукт отличается

Аналоги на рынке уже есть, и «мы тоже умеем читать справочники» продажу не закрывает. Отличие должно быть заложено в архитектуру на старте — доклеить его в четвёртой фазе не получится.

1. **Семантический слой.** Агент ошибается не потому, что не может прочитать таблицу, а потому что не понимает, что `КонтрагентВид` — это тип контрагента. Описания, синонимы и примеры хранятся в базе и правятся консультантом на внедрении.
2. **Двухуровневые инструменты.** В ERP десятки тысяч объектов — отдать агенту тысячу MCP-инструментов невозможно. Сначала discovery (поиск по метаданным, описание объекта), потом исполнение. Контекст модели остаётся рабочим.
3. **Dry-run перед записью.** Агент получает предпросмотр: что будет создано, какие проверки заполнения пройдены, что произойдёт при проведении. Запись — вторым вызовом по токену подтверждения. Без этого ни один финдиректор запись не согласует.
4. **Идемпотентность.** Ключ идемпотентности на создание. Агент, который ретраит вызов после таймаута, не порождает второй документ реализации — типовая беда наивных интеграций.
5. **Аудит с откатом.** Журнал в бизнес-терминах, со ссылками на созданные объекты и групповой отменой проведения по сессии агента. Это то, что показывают службе внутреннего контроля.
6. **Данные не отдают команд.** Содержимое полей 1С возвращается помеченным как данные. Шлюз не исполняет инструкции, пришедшие из комментария к документу, — защита от инъекций через справочные данные.

## 04 · Дорожная карта

Шесть фаз со сквозным сценарием: каждая заканчивается работающим end-to-end путём от агента до базы, а не набором готовых модулей. Недели — календарные, при заявленном составе команды.

### Ф0 · Фундамент и контракт API — недели 1–2

Единственная фаза без кода продукта. Цена ошибки в контракте API растёт кратно после первого клиента, поэтому спецификация пишется до реализации.

- ADR по архитектуре, регламент clean room, шаблон репозитория
- Сборка `.cfe` из исходников в CI (1C:EDT либо OneScript + gitsync), автотесты на Vanessa/ADD
- Стенды: УТ 11, ERP 2, БП 3.0 и одна самописная база клиента
- Черновик OpenAPI 3.1 на весь v1 — включая операции будущих фаз

> **Готово когда:** пустое расширение собирается в CI, ставится на все четыре стенда и отвечает на `/v1/health`.

### Ф1 · Чтение и интроспекция — недели 3–7

Ядро продукта. Здесь же решается вопрос, который позже переделать дороже всего: как метаданные большой конфигурации помещаются в контекст модели.

- HTTP-сервис, аутентификация по токену, скоупы, журнал вызовов
- Интроспекция метаданных с ленивой загрузкой и кэшем; семантический словарь
- Чтение справочников, документов, регистров: фильтры, пагинация, выборка по ссылке
- MCP-шлюз с discovery-инструментами; подключение из Claude Desktop

> **Готово когда:** агент отвечает на «сколько было отгрузок за август по контрагенту N и на какую сумму» на стенде ERP — без предварительной настройки под этот вопрос.

### Ф2 · Отчёты и запросы — недели 8–10

Отчёты СКД — это готовая, выверенная бухгалтерией бизнес-логика. Дать агенту запускать их дешевле и надёжнее, чем учить его собирать те же цифры запросом.

- Запуск отчётов СКД с параметрами, вывод в JSON, Markdown и CSV
- Именованные запросы с типизированными параметрами и схемой результата
- Валидатор произвольного запроса: разбор текста, только выборка, лимиты строк и времени, запрет опасных конструкций
- Фоновые задания и `/v1/job` для длительных операций

> **Готово когда:** агент запускает типовой отчёт с параметрами и получает результат, а тяжёлый запрос уходит в фон и корректно отдаёт статус и результат по job-id.

### Ф3 · Запись и бизнес-логика — недели 11–15

Самая рискованная фаза: здесь агент начинает менять данные клиента. Механики доверия — dry-run, идемпотентность, откат — делаются вместе с записью, а не после.

- Создание и изменение объектов, проведение, транзакционность
- Dry-run с предпросмотром и токеном подтверждения; ключи идемпотентности
- Ошибки проведения и проверки заполнения — в формулировках, из которых агент понимает, что исправить
- Whitelist экспортных процедур конфигурации как инструментов
- Групповой откат по сессии агента

> **Готово когда:** агент создаёт и проводит документ на стенде УТ, повторный вызов не порождает дубль, а вся сессия откатывается одной операцией.

### Ф4 · Продуктизация — недели 16–21

Переход от «работает у нас» к «ставится у клиента без нас». Для тиражного продукта это не хвост проекта, а половина его стоимости.

- Админ-панель в 1С (`мкпАдминистрированиеКоннектора`): генерация токена (plaintext один раз, в справочник SHA-256), чеклист публикации, самодиагностика
- `GET /v1/diag` адаптера, `GET /diag` шлюза, MCP `diag`
- Дистрибутив: исходники `.cfe` + Docker Compose и Helm-чарт шлюза
- Версионирование, политика совместимости с 8.3.20+ и обоими режимами работы (файловый и клиент-серверный)
- Документация внедренца и администратора

**Вне этой фазы (отложено по решению заказчика продукта):** лицензирование и DRM самого 1cmcp; OAuth шлюза; нагрузочное тестирование; внешний пентест публикации; обучение партнёрской сети. Клиентские лицензии платформы 1С (сеансы HTTP-сервиса) — [ADR-0004](docs/adr/0004-sessions-and-licenses.md), не ключ продукта.

> **Готово когда:** инженер, не участвовавший в разработке, разворачивает коннектор на незнакомой базе по документации за рабочий день — без ключа продукта.

### Ф5 · Пилоты и развитие — после RC

Два-три пилота на разных типах конфигураций, дальше — библиотека готовых сценариев, которая и продаёт продукт: не «API к 1С», а «согласование заявок голосом», «сборка отчётности по звонку», «ввод первички из почты».

**В репозитории (0.6.0):**

- Каталог сценариев `guide` (MCP и `GET /guide`), playbook записи только через dry-run
- Пресеты подключения: Claude Desktop, Cursor, n8n — `docs/connect/`
- Семена семантического словаря из публичных имён типовых (`dictionary_seed`)
- Чек-листы пилота и реестра ПО

**В репозитории (0.7.0, хвост слоя B):** MCP streamable HTTP на `/mcp`, `ONEC_TENANTS` / `/t/{tenant}/v1`, rate limit, лимиты суммы и количества на `мкпКлиентыИнтеграции`, спаны OpenTelemetry. WAF — на периметре оператора.

**Вне репозитория:** живые пилоты на базах клиентов; подача заявки в реестр отечественного ПО; первая продажа через партнёрский офис. Лицензирование продукта 1cmcp по-прежнему отложено.

> **Готово когда (бизнес):** первая продажа коннектора идёт через партнёрский офис, а не через команду разработки.
> **Готово когда (git):** партнёрский инженер подключает агента по `docs/connect` и прогоняет каталог `GET /guide` без правки кода.

## 05 · Команда и оценка

Состав рассчитан на срок до релиз-кандидата. Роль архитектора не совмещается с разработкой: контракт API и правовой регламент требуют отдельного владельца.

| Роль | FTE | Зона ответственности |
|---|---|---|
| Архитектор / тимлид | 1,0 | Контракт API, ADR, регламент clean room, приёмка |
| Разработчик 1С | 2,0 | Расширение: интроспекция, данные, запросы, отчёты, админ-панель |
| Backend-разработчик | 1,0 | Шлюз, MCP и OpenAPI, инфраструктура, наблюдаемость |
| QA | 0,5 | Автотесты на четырёх стендах, нагрузка, регресс при обновлении типовых |
| Технический писатель | 0,5 | Документация внедренца, администратора и разработчика сценариев |

Отдельно, вне FTE: юридическая проверка регламента и товарного знака. Внешний пентест — перед пилотами (Ф5), не блокер Ф4. Лицензирование продукта 1cmcp не входит в объём до отдельного решения.

## 06 · Риски

Первые два способны обнулить экономику продукта, поэтому проверяются в нулевой и первой фазах, а не когда обнаружатся у клиента.

| Риск | Уровень | Что делаем |
|---|---|---|
| **Клиентские лицензии 1С.** Каждый сеанс HTTP-сервиса занимает лицензию; десяток агентов способен выесть их у живых пользователей | Высокий | Просчитать модель сеансов в Ф0, пул с переиспользованием, перенос тяжёлого в фоновые задания, явная рекомендация по лицензиям в документации |
| **Ошибочная запись агентом.** Галлюцинация модели превращается в проведённый документ | Высокий | Dry-run и подтверждение обязательны, а не опциональны; лимиты сумм и количеств на клиента интеграции; групповой откат; полный аудит |
| **Публикация наружу.** HTTP-сервис 1С в интернете — классический вектор атаки | Высокий | 1С доступна только шлюзу: mTLS или VPN, никакой прямой публикации; rate limit и WAF на шлюзе; пентест перед пилотами |
| **Объём метаданных ERP.** Полная интроспекция десятков тысяч объектов не помещается ни в память, ни в контекст модели | Средний | Ленивая загрузка, кэш с версионированием, discovery вместо выгрузки всего, ограничение области видимости правилами доступа |
| **Обновления типовых конфигураций.** Заимствованные объекты ломают штатное обновление у клиента | Средний | Минимум заимствований, только расширяющие методы; регресс-тесты на каждом релизе типовых; матрица поддерживаемых версий |
| **Конкуренция.** Похожие решения на рынке уже есть | Средний | Дифференциация из раздела 03 закладывается в Ф1–Ф3; канал продаж через партнёрскую сеть — преимущество, которое конкурентам не скопировать |
| **Дрейф спецификации MCP.** Протокол меняется быстрее релизного цикла 1С | Низкий | Именно поэтому MCP живёт в шлюзе: обновляется контейнер, расширение у клиента не трогается |

## 07 · Первая неделя

Цель недели — не документы, а работающий сквозной скелет: запрос из агента доходит до базы и возвращает реальные данные. Всё остальное потом наращивается на него.

- **Дни 1–2 · Контур.** Стенд УТ 11, публикация на веб-сервере, пустое расширение с одним HTTP-сервисом, отвечающим `200 OK`. Заодно замеряется занятие лицензии на сеанс — цифра нужна для главного риска.
- **День 3 · Контракт.** Черновик OpenAPI на `/v1/meta` и `/v1/data`: как выглядит ссылка, дата, табличная часть и ошибка. Дальше этот формат менять дорого.
- **Дни 4–5 · Сквозной прототип.** Интроспекция одного справочника → JSON → MCP-инструмент в шлюзе → живой запрос из Claude Desktop. Скелет собран.
- **Итог недели · Демо и решение.** Показ прототипа заказчику продукта, подтверждение бюджета Ф0–Ф1 и фиксация регламента clean room до того, как написана первая строка продуктового кода.
