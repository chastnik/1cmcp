# ADR 0014. Просмотр сессии перед откатом

- Статус: принято
- Дата: 2026-09-10
- Фаза: Ф8

## Контекст

Ф3 дал `POST /v1/session/rollback` без возможности увидеть, что будет отменено. Ф7 открыл журнал вызовов, но не список операций сессии. Служба внутреннего контроля должна сначала посмотреть сессию, потом откатывать. Идентификатор сессии задаёт агент (`X-Session-Id`), поэтому откат без фильтра по клиенту интеграции опасен.

## Решение

1. Версия **0.9.0**.
2. **`GET /v1/session/{session_id}`**, скоуп `read`. Только операции этого Bearer. Пустая или чужая сессия — `200` и `items: []`. Поля элемента: `op`, `kind`, `name`, `id`. Порядок — как записывали.
3. MCP **`session_get`**.
4. Откат фильтрует операции по клиенту; чужой `session_id` не трогает чужие записи.
5. В журнале вызовов — ресурс `Сессия` / поле `session_id`, фильтр `?session=`.

## Последствия

- Агент и администратор видят состав сессии до `session_rollback`.
- Совпадение строки `X-Session-Id` у двух клиентов больше не откатывает чужие документы.
