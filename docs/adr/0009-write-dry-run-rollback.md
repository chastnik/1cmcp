# ADR 0009. Запись, dry-run, идемпотентность и откат

- Статус: принято
- Дата: 2026-09-09
- Фаза: Ф3

## Контекст

Ошибочная запись агентом — главный продуктовый риск. Проведённый документ из галлюцинации нельзя «просто удалить» в учёте. Dry-run, ключ идемпотентности и групповой откат сессии должны появиться вместе с первым POST записи, а не после пилота.

Пустой ACL по ADR-0006 по-прежнему даёт только `read`. Скоуп `write` без whitelist объекта запись не открывает.

## Решение

### Dry-run и confirm_token

`POST /v1/data/{kind}/{name}/dry-run` не фиксирует объект. Ответ: `confirm_token` (TTL 600 с), `preview`, `fill_check` (формулировки, что исправить), при `post: true` — ещё `posting_effects`. Без токена `POST`/`PATCH`/`…/post` отвечают `400 confirm_required`. Токен привязан к виду/имени и отпечатку тела (без `id`/`ref`); для проведения — к `id` объекта (`consume_for_target`).

### Запись

- `POST /v1/data/{kind}/{name}` — создание, `201`, тело `WriteRequest` (`item`, `confirm_token`, `post`).
- `PATCH /v1/data/{kind}/{name}/{id}` — изменение.
- `POST /v1/data/{kind}/{name}/{id}/post` — проведение; ошибка платформы — `422 posting_failed`.
- Обязательный заголовок `Idempotency-Key` (8–128). Повтор с тем же ключом и тем же телом возвращает сохранённый результат. Другое тело — `409 idempotency_conflict`.
- Необязательный `X-Session-Id` для журнала операций сессии.

### Действия и откат

`POST /v1/action` вызывает только имя из whitelist (на моке `DemoPostShipment`; в 1С — справочник `мкпДействияИнтеграции`). Неизвестное имя — `404`. `POST /v1/job` с `operation: action` остаётся `501`: живой путь — `/v1/action`.

`POST /v1/session/rollback` с `{session_id}` откатывает create/patch/post этой сессии (мок удаляет созданное и снимает проведение; расширение помечает на удаление / отменяет проведение).

### MCP

Инструменты `data_dry_run`, `data_create`, `data_patch`, `data_post`, `action`, `session_rollback`. Агент сначала dry-run, затем запись с токеном и ключом.

### Объекты расширения Ф3

- модуль `мкпДействия`
- справочник `мкпДействияИнтеграции`
- регистры `мкпКлючиИдемпотентности`, `мкпТокеныПодтверждения`, `мкпОперацииСессии`

Имена не пересекаются с модулем `мкпЗадания` / регистром `мкпСостоянияЗаданий`.

## Последствия

- Агент создаёт и проводит документ, повтор с тем же ключом не плодит дубль, сессия откатывается одним вызовом.
- Токен `dev-token` (только `read`) писать не может. Стенд записи: `dev-write-token`.
- Админ-мастер, дистрибутив и лицензии — Ф4.
