# ADR 0008. Отчёты СКД, именованные запросы и фон

- Статус: принято
- Дата: 2026-09-09
- Фаза: Ф2

## Контекст

Фаза 1 научила агента находить объекты и читать выборки. «Отчёт по продажам» там — сумма документов. Бухгалтерия доверяет цифрам типового СКД. Произвольный запрос без валидатора — путь к изменению данных и к исчерпанию лицензий. Длинная компоновка не должна держать HTTP-сеанс.

## Решение

### Отчёт

`POST /v1/report` с `name`, необязательными `variant` / `parameters`, `format`: `json` | `markdown` | `csv`. Ответ — `content_kind: data`. Неизвестное имя — `404`. MCP-инструмент `report`. На моке стенда — `DemoSales` (август 2026, те же фикстуры отгрузок). В типовой базе имя из пресета, обычно `Продажи`; агент подтверждает наличие через `meta_describe`.

`guide` для сценария продаж сначала предлагает `report`, затем fallback на `data_list`.

### Запрос

`POST /v1/query`: ровно одно из `named_query` или `text`.

Именованные запросы живут в справочнике `мкпИменованныеЗапросы` (текст, схемы параметров и результата, лимит, таймаут). Это безопасная альтернатива произвольному тексту.

Произвольный текст проходит валидатор: только выборка (`ВЫБРАТЬ` / `SELECT`), без `;`, `ВЫПОЛНИТЬ` / `EXECUTE`, `УНИЧТОЖИТЬ` / `DROP`, `ПОМЕСТИТЬ` / `INTO`, `ДЛЯ ИЗМЕНЕНИЯ` / `FOR UPDATE`, `DELETE` / `UPDATE` / `INSERT` / `MERGE`. Лимит строк 1–10000 (по умолчанию 1000), длина текста ≤ 20000. Отказ — `400` `query_rejected`.

Шлюз повторяет те же правила в `onecmcp.query_validator` до/вместе с моком; живая 1С проверяет в модуле `мкпЗапросы`.

### Фон

`async: true` на query/report и `POST /v1/job` отвечают `202` `{job_id, status}`. `GET /v1/job/{id}` — `queued|running|succeeded|failed` и `result` либо `error`. Состояние в регистре `мкпСостоянияЗаданий` (не путать с модулем `мкпЗадания`). `operation: action` остаётся `501` до Ф3. Живой whitelist — `POST /v1/action` (ADR-0009).

На моке задание выполняется сразу, GET отдаёт `succeeded` с результатом — контракт job-id соблюдён без платформенных фоновых заданий.

### Объекты расширения Ф2

- модули `мкпЗапросы`, `мкпОтчёты`, `мкпЗадания`
- справочник `мкпИменованныеЗапросы`
- регистр `мкпСостоянияЗаданий`

## Последствия

- Агент запускает типовой отчёт с параметрами периода и получает JSON/Markdown/CSV.
- Тяжёлый запрос уходит в фон и читается по `job_id`.
- Произвольный запрос не может быть командой изменения.
- Запись документов, dry-run и whitelist действий реализованы в Ф3 (ADR-0009). `operation: action` в `/v1/job` по-прежнему `501`; живой путь — `POST /v1/action`.
