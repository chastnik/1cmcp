# ADR 0004. Сеансы HTTP-сервиса и клиентские лицензии

- Статус: принято
- Дата: 2026-09-09
- Фаза: Ф0

## Контекст

Каждый сеанс HTTP-сервиса 1С занимает клиентскую лицензию. Десяток агентов способен выесть лицензии у живых пользователей. Это главный экономический риск продукта; модель сеансов фиксируется в Ф0, до чтения данных.

Платформа даёт повторное использование сеансов интернет-сервисов (свойства HTTP-сервиса и публикация в `default.vrd`). См. руководство разработчика 1С, глава «Механизмы интернет-сервисов», раздел о повторном использовании сеансов.

## Решение

1. У HTTP-сервиса `мкпAPI`: `ReuseSessions = AutoUse`, `SessionMaxAge = 20` секунд. Короткое окно держит пул тёплым на пачку вызовов агента и отпускает лицензию, если агент молчит.
2. Шлюз переиспользует HTTP-соединения (keep-alive) к одной базе и не открывает параллельный сеанс на каждый инструмент MCP без нужды. В Ф1 — явный пул на тенанта с верхней границей.
3. Длительные операции (отчёты СКД, тяжёлые запросы) уходят в `/v1/job` и фоновые задания 1С, а не держат интерактивный сеанс HTTP на всё время расчёта.
4. Документация внедренца обязана содержать расчёт: число одновременных сеансов шлюза ≈ число занятых лицензий. Рекомендация по отдельному пулу лицензий для интеграции — не опция, а требование пилота.
5. На стенде УТ 11 в контуре Ф0 замеряется факт занятия лицензии на один запрос `/v1/health` при `AutoUse` и при `DontUse`. Цифра фиксируется в отчёте стенда, не в этом ADR.

Прямой доступ агентов к HTTP-сервису 1С запрещён: только шлюз. Это ограничивает число сеансов числом воркеров шлюза, а не числом чатов.

## Последствия

- Health и короткие чтения делят сеанс.
- Оценка лицензий для КП — измерение, а не догадка.
- Если замер на конкретной платформе клиента покажет иное поведение `AutoUse`, допускается смена `SessionMaxAge` без смены контракта API.
