# ADR 0006. Аутентификация, ленивая интроспекция и ACL по умолчанию

- Статус: принято
- Дата: 2026-09-09
- Фаза: Ф1

## Контекст

Фаза 1 открывает чтение метаданных и данных. Три решения нельзя откладывать: кто имеет право вызывать API, как ERP с десятками тысяч объектов не попадает целиком в контекст модели, и что видно клиенту, пока консультант не заполнил матрицу доступа.

## Решение

### Аутентификация слоя A

`Authorization: Bearer <token>`. Токен сопоставляется элементу справочника `мкпКлиентыИнтеграции` по SHA-256 хешу. В объекте — скоупы и сопоставленный пользователь ИБ.

`GET /v1/health` остаётся без токена: это самодиагностика публикации и контура. `meta` и `data` без действительного Bearer отвечают `401` (`application/problem+json`, `code: unauthorized`). Нет скоупа `read` — `403`.

Вызовы `meta`/`data` пишутся в `мкпЖурналВызовов`. Сбой журнала не ломает ответ агенту.

Демо-стенд и CI используют токен `dev-token`.

### Ленивая интроспекция

Агенту не отдаётся полное дерево метаданных. Discovery двухуровневый:

1. `GET /v1/meta` — страница `kind`/`name`/`synonym` (курсор, лимит).
2. `GET /v1/meta/search?q=` — поиск по имени, синониму и регистру `мкпСемантическийСловарь`.
3. `GET /v1/meta/{kind}/{name}` — карточка одного объекта: поля, табличные части, примеры.

Шлюз кэширует ответы метаданных с TTL (`META_CACHE_TTL_SECONDS`, по умолчанию 60 с). Выборка `data` не кэшируется.

Объекты с префиксом `мкп` агенту не видны: это служебные объекты расширения.

### ACL по умолчанию

Регистр `мкпПравилаДоступа` — матрица клиент × вид × имя × операция. Если для клиента нет ни одной записи, разрешено только `read` чужих (не `мкп*`) объектов. Появление любой записи переводит клиента в явный whitelist: разрешено только то, что отмечено `Разрешено = Да`.

Запись данных в Ф1 отсутствует; `POST /v1/data` и проведение в той фазе отвечали `501`. С Ф3 запись включена при скоупе `write` и whitelist — [ADR-0009](0009-write-dry-run-rollback.md). Пустой ACL по-прежнему только `read`.

## Последствия

- Консультант может подключить агента к чтению без предварительной настройки матрицы.
- Узкий whitelist включается добавлением правил, а не отдельным режимом.
- Контекст модели остаётся рабочим на ERP: сначала поиск, потом карточка, потом выборка с фильтром.
