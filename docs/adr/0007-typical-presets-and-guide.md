# ADR 0007. Пресеты типовых конфигураций и навык guide

- Статус: принято
- Дата: 2026-09-09
- Фаза: Ф1 (задел на Ф2/Ф5)

## Контекст

На УТ, КА, ERP и Бухгалтерии пользователь спрашивает по-человечески: «покажи отчёт по продажам за период», «сколько пришло заказов». Имена метаданных другие: `РеализацияТоваровУслуг`, `ЗаказКлиента`, в БП вместо заказа — `СчетНаОплатуПокупателю`.

Отдать агенту по инструменту на каждый документ ERP нельзя: контекст модели кончится. Консультант не должен перед каждым вопросом заполнять словарь. Каталог сценариев в плане отнесён к Ф5, отчёты СКД — к Ф2, но без подсказок по типовым именам Ф1 на живой УТ не отвечает на простые фразы.

## Решение

Три слоя, не тысяча MCP-tools.

1. **Пресет-словарь** (`onecmcp.presets`, JSON в пакете). Синонимы публичных имён типовых конфигураций (источник — описание на ИТС, не чужие `.cfe`). Выбор: `ONEC_PRESET=auto|ut11|ka2|erp2|bp30|none`.
2. **Смешение в `meta_search`.** Ответ адаптера 1С идёт первым; затем подсказки пресета с `source: preset`. Агент обязан `meta_describe`: 404 значит, что объекта в этой базе нет.
3. **Инструмент `guide`.** Разбирает фразу и возвращает шаги (`meta_search` → `meta_describe` → `data_list` + какое поле суммировать). В 1С не ходит. Для «отчёта по продажам» в Ф1 это выборка документов и сумма `СуммаДокумента`, с явной оговоркой: типовой СКД-отчёт — фаза 2.

Навыки для Cursor/Claude — markdown-плейбуки в `skills/`; они не заменяют MCP, а учат модель вызывать `guide`.

КА 2 и ERP 2 расширяют словарь УТ 11 (общие документы продаж/закупок).

## Последствия

- На свежей УТ вопрос «сколько заказов» решается без заполнения `мкпСемантическийСловарь`.
- Самописная база: `ONEC_PRESET=none` или свой словарь в 1С.
- Цифры «отчёта» в Ф1 — оперативные, не бухгалтерский СКД. Когда появится `/v1/report`, `guide` начнёт указывать на отчёт, не ломая discovery.
