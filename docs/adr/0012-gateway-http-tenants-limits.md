# ADR 0012. HTTP-транспорт MCP, лимиты и тенанты на шлюзе

- Статус: принято
- Дата: 2026-09-10
- Фаза: хвост слоя B после Ф5

## Контекст

Ф0–Ф5 закрыли контракт v1, запись и каталог сценариев. В ADR-0001 и плане слоя B оставались пункты без кода: MCP streamable HTTP, маршрутизация нескольких ИБ, rate limit на шлюзе, трассировка OpenTelemetry. В таблице рисков — лимиты суммы и количества на клиента интеграции. OAuth, DRM, WAF и живые пилоты по-прежнему вне git.

## Решение

1. Версия **0.7.0**.
2. **MCP streamable HTTP.** `python -m onecmcp serve` монтирует MCP на `MCP_HTTP_PATH` (по умолчанию `/mcp`). Отдельный процесс: `python -m onecmcp mcp --transport streamable-http`. stdio без флага — как раньше, для Claude Desktop.
3. **Тенанты.** `ONEC_TENANTS` — CSV `id=url` или JSON. Заголовок `X-Tenant` или путь `/t/{tenant}/v1/...`. Неизвестный id — `404 unknown_tenant`. Один процесс шлюза, контракт JSON один.
4. **Rate limit.** `RATE_LIMIT_PER_MINUTE` (по умолчанию 120), скользящее окно по хешу Bearer или IP. `/health` и `/ready` не считаются. Отказ — `429 rate_limited` и `Retry-After`. WAF остаётся на периметре оператора.
5. **OpenTelemetry.** Спан `http.request` на каждый запрос шлюза. Экспорт OTLP — если задан `OTEL_EXPORTER_OTLP_ENDPOINT` и установлен extra `otel`.
6. **Лимиты записи.** Реквизиты `мкпКлиентыИнтеграции.ЛимитСуммы` и `ЛимитКоличества` (0 — нет лимита). Мок и расширение: предупреждение в `fill_check` dry-run, запись — `400 limit_exceeded`.

OAuth шлюза, лицензирование продукта, пентест и подача в реестр ПО не входят в это решение.

## Последствия

- HTTP-агенты (Cursor по URL, внутренние сервисы) подключаются к одному процессу `serve`.
- Несколько информационных баз не требуют нескольких контейнеров шлюза.
- Ошибочная сумма агента режется на клиенте интеграции, не только dry-run'ом платформы.
