# ADR 0005. Режим clean room

- Статус: принято
- Дата: 2026-09-09
- Фаза: Ф0

## Контекст

Универсальному коннектору нужны своя модель безопасности, своя интроспекция и свой контракт API. Переписывание чужого расширения не даёт этих свойств и создаёт правовой риск.

## Решение

Источники, из которых разрешено проектировать и писать код:

- официальная документация 1С и ИТС: HTTP-сервисы, публикация на веб-сервере, расширения конфигурации, повторное использование сеансов, права ролей, JSON в языке 1С;
- спецификации MCP, OpenAPI 3.1, RFC 7807, OAuth 2.0;
- этот репозиторий.

Запрещено:

- декомпиляция, дизассемблирование и загрузка сторонних `.cfe` / `.epf` / выгрузок конкурирующих коннекторов;
- копирование имён общих модулей, HTTP-сервисов, ролей, справочников, UUID и текстов модулей из чужих продуктов;
- «сверка с аналогом» по двоичному файлу или дампу метаданных.

Публичные факты платформы (публикация на веб-сервере, роль и права, вызов HTTP-сервиса) — описание механизмов 1С, общих для всех. Их использование не требует чужого кода.

Происхождение фиксируется: git, ADR на архитектурные решения, чек-лист приёмки.

Подробный регламент: [`docs/clean-room.md`](../clean-room.md).

## Последствия

- Медленнее старт, меньше правового хвоста.
- Код и UUID в репозитории — доказательная база при споре.
