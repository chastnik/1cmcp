# ADR 0010. Продуктизация без лицензирования продукта

- Статус: принято
- Дата: 2026-09-09
- Фаза: Ф4

## Контекст

Ф4 в исходном плане смешивала «ставится без нас» с лицензированием и защитой тиража 1cmcp, нагрузкой, пентестом и обучением партнёров. Лицензирование **самого продукта** (DRM, ключи, защита дистрибутива) не планируется. Это не отменяет ADR-0004: сеанс HTTP-сервиса по-прежнему занимает **клиентскую лицензию платформы 1С**.

Критерий фазы не меняется: инженер не из команды разработки разворачивает коннектор по документации за рабочий день.

## Решение

1. Версия **0.5.0**. Ключ продукта отсутствует: поле `product_license` в диагностике всегда `not_required`. Генерации серийников, онлайн-активации и обфускации `.cfe` нет.
2. Самодиагностика:
   - адаптер `GET /v1/diag` без Bearer (как health): версия, 8.3.20+, режимы file/client_server, RootURL `mcp`, AutoUse, роль;
   - шлюз `GET /diag`: пресет, TTL кэша, host адаптера, доступность слоя A, без токена и секретов;
   - MCP-инструмент `diag`.
3. Обработка `мкпАдминистрированиеКоннектора`: plaintext токена один раз, в справочник `мкпКлиентыИнтеграции` только SHA-256; чеклист публикации (не кликер IIS/Apache); вызов самодиагностики.
4. Дистрибутив: исходники расширения + `docker-compose.yml` с healthcheck + Helm-чарт `deploy/helm/onecmcp`. Политика совместимости — `docs/compatibility.md`.
5. **Отложено:** OAuth шлюза, нагрузочное тестирование, внешний пентест, обучение партнёрской сети, заявка в реестр ПО (Ф5).

## Последствия

- Пилот и внутренние внедрения не блокируются ключом продукта.
- Оценка клиентских лицензий 1С остаётся в документации внедренца.
- Админ-мастер, дистрибутив и лицензии продукта из хвоста ADR-0009 закрыты этим решением (лицензии продукта — отложены, остальное — сделано).
