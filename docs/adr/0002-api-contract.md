# ADR 0002. Контракт HTTP API v1

- Статус: принято
- Дата: 2026-09-09
- Фаза: Ф0

## Контекст

Цена ошибки в формате ссылки, даты, табличной части и ошибки растёт после первого клиента. Черновик OpenAPI пишется до продуктовой реализации чтения и записи.

Каноническая спецификация: [`specs/openapi.yaml`](https://github.com/chastnik/1cmcp/blob/main/specs/openapi.yaml).

## Решение

### Базовый URL слоя A

После публикации ИБ на веб-сервере:

```
https://{host}/{ib}/hs/mcp/v1/...
```

Корневой URL HTTP-сервиса расширения — `mcp`. Версия API — префикс пути, не заголовок.

### Типы

| Тип 1С | JSON |
|---|---|
| Ссылка | объект `Ref`: `ref` (полное имя метаданных), `id` (UUID), `presentation` |
| `Дата` | `YYYY-MM-DD` |
| `Дата` со временем / универсальная | `YYYY-MM-DDTHH:mm:ssZ` (UTC) |
| Табличная часть | массив объектов |
| `ХранилищеЗначения`, двоичные данные | не возвращаются телом; метаданные поля помечают `binary: true` |
| `Неопределено` / пустая ссылка | `null` |
| Булево, число, строка | JSON boolean / number / string |

Имя поля `ref`, а не `type`: последнее конфликтует с JSON Schema и с полем вида номенклатуры в данных.

### Ошибки

[RFC 7807](https://www.rfc-editor.org/rfc/rfc7807) `application/problem+json`:

```json
{
  "type": "https://1cmcp.dev/errors/not-implemented",
  "title": "Not implemented",
  "status": 501,
  "detail": "Операция появится в следующей фазе",
  "code": "not_implemented"
}
```

### Пагинация

Курсорная: `limit` + `cursor`. Ответ: `items`, `next_cursor`, `has_more`. Лимит по умолчанию 50, максимум 500.

### Аутентификация слоя A

`Authorization: Bearer <token>`. Токен сопоставляется клиенту интеграции (Ф1). `/v1/health` в Ф0 отвечает без скоупов, чтобы снять контур; с Ф1 health тоже требует токен, кроме режима самодиагностики с локальной сети.

### Запись (Ф3, в контракте уже сейчас)

- Заголовок `Idempotency-Key` на создание.
- Dry-run — отдельная операция, запись — вторым вызовом с токеном подтверждения.
- Данные из 1С помечаются как данные: заголовок `X-1cmcp-Content-Kind: data` и поле `content_kind` в конверте выборки. Шлюз не исполняет инструкции из значений полей.

### Нереализованные операции

Ф1–Ф4 закрыли чтение, отчёты, запись, админ-чеклист и самодиагностику. Слой A отвечает `501` `not_implemented` на неизвестный путь и на `POST /v1/job` с `operation: action` (живой вызов — `/v1/action`). OAuth шлюза отложен. Лицензионный ключ продукта не выдаётся. Менять форму уже описанных ресурсов без новой мажорной версии нельзя.

## Последствия

- Шлюз, мок и расширение разделяют одну схему.
- Клиенты Ф1 могут писать адаптеры к `meta`/`data` до готовности записи.
- Расширение не знает про MCP: агентные инструменты собирает слой B.
