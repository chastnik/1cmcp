# Диагностика и клиентские лицензии 1С

Ключ продукта 1cmcp не существует. Путают с **клиентской лицензией платформы**: каждый сеанс HTTP-сервиса её занимает ([ADR-0004](../adr/0004-sessions-and-licenses.md)).

## Что смотреть

| Куда | Токен | Что видно |
|---|---|---|
| `GET /v1/health` | нет | живость адаптера |
| `GET /v1/diag` | нет | платформа 8.3.20+, RootURL `mcp`, AutoUse, роль, `product_license=not_required` |
| `GET /health` шлюза | нет | процесс шлюза |
| `GET /ready` | нет | шлюз достучался до адаптера; иначе 503 |
| `GET /diag` шлюза | нет | пресет, TTL, тенанты, `/mcp`, rate limit, host адаптера **без** `ONEC_TOKEN` |
| MCP `diag` | — | то же, что `/diag` |

Обработка `мкпАдминистрированиеКоннектора` повторяет чеклист публикации и самодиагностику.

## Как изменить поведение сеансов 1С

У HTTP-сервиса `мкпAPI` в расширении:

| Свойство | Значение в поставке | Зачем | Как изменить |
|---|---|---|---|
| `RootURL` | `mcp` | путь `/hs/mcp` | только вместе с публикацией и `ONEC_BASE_URL` |
| `ReuseSessions` | `AutoUse` | пачка вызовов агента делит сеанс | Конфигуратор, расширение |
| `SessionMaxAge` | `20` секунд | простой отпускает лицензию | Конфигуратор; можно без смены API |

Грубая оценка для пилота: **число одновременных сеансов шлюза ≈ число занятых лицензий**. Не направляйте чаты напрямую в `/hs/mcp`. Отдельный пул лицензий для интеграции — требование пилота.

## Rate limit и трассировка

- `RATE_LIMIT_PER_MINUTE` (умолчание 120, окно 60 с): ключ — хеш Bearer или IP. Превышение → `429` `rate_limited`, заголовок `Retry-After`. Не считаются `/`, `/health` и `/ready`.
- `OTEL_EXPORTER_OTLP_ENDPOINT`: спан `http.request`. Нужен `pip install 'onecmcp[otel]'`. Пусто — спаны без экспорта.

Как поменять числа — [справочник настроек](../reference/settings.md) и [как изменить](how-to-change.md).
