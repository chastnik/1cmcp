# Регламент clean room

Проект 1cmcp разрабатывается с нуля. Этот документ обязателен для всех, кто пишет код, спецификации, тесты и документацию.

## Цель

Исключить заимствование чужих расширений и исходников конкурирующих MCP/API-коннекторов к 1С. Собственные имена, UUID, структура API и модель безопасности.

## Разрешённые источники

1. Документация платформы 1С:Предприятие 8.3 (ИТС, руководство разработчика): HTTP-сервисы, расширения, роли, JSON, публикация на веб-сервере, повторное использование сеансов.
2. Открытые спецификации: MCP, OpenAPI 3.1, JSON Schema, RFC 7807, OAuth 2.0 / RFC 6749.
3. Исходники и ADR этого репозитория.
4. Публичные описания типовых конфигураций (имена справочников УТ/ERP/БП) — только как примеры стендов, не как копирование чужого API.

## Запрещено

- Получать, открывать, декомпилировать, сравнивать и цитировать сторонние `.cfe`, `.cf`, `.epf` и выгрузки конфигурации продуктов-аналогов.
- Переносить UUID, имена объектов метаданных, тексты модулей, тексты ролей и структуру URL из аналогов.
- Просить коллег «посмотреть, как сделано у них в расширении» и пересказывать устройство чужого кода.

Нарушение останавливает приёмку коммита. Спорный фрагмент удаляется и пишется заново автором, который чужой код не видел.

## Именование

Префикс собственных объектов — `мкп`. Продуктовое имя — `1cmcp`. Пакет шлюза — `onecmcp`. Совпадение имён с чужими продуктами недопустимо; при обнаружении — переименование до мержа.

## Фиксация происхождения

- Коммиты в git с осмысленным сообщением.
- ADR в `docs/adr/` на каждое решение уровня архитектуры или контракта.
- Чек-лист приёмки: [`docs/acceptance-checklist.md`](acceptance-checklist.md).

## Приёмка изменения, затрагивающего расширение или API

Автор подтверждает:

1. Код написан по документации платформы / спецификации репозитория, а не по чужому дампу.
2. Новые UUID сгенерированы в этом репозитории.
3. Имена объектов несут префикс `мкп` либо принадлежат слою B (Python) и не маскируются под чужой продукт.

Рецензент вправе запросить источник конкретного решения (пункт ИТС, ADR, OpenAPI).
