# Чек-лист приёмки

Используется в ревью и перед сборкой дистрибутива.

## Clean room

- [ ] Нет заимствований из сторонних `.cfe` / выгрузок аналогов
- [ ] Новые UUID сгенерированы в репозитории, не скопированы
- [ ] Имена объектов расширения начинаются с `мкп`
- [ ] Нет заимствованных объектов типовой конфигурации без отдельного ADR

## Контракт

- [ ] Изменение JSON согласовано с `specs/openapi.yaml`
- [ ] Ошибки — `application/problem+json`
- [ ] Ссылки сериализуются как `Ref` (`ref`, `id`, `presentation`)
- [ ] Выборка данных помечена `content_kind: data`

## Расширение

- [ ] Назначение `AddOn`, совместимость 8.3.20+
- [ ] HTTP-сервис отвечает на `GET /v1/health` и `GET /v1/diag` кодом 200 и JSON контракта
- [ ] `meta`/`data` без Bearer — `401`; объекты `мкп*` агенту не видны
- [ ] `ReuseSessions = AutoUse`
- [ ] Роль `мкпДоступКоннектора` минимальна
- [ ] Обработка `мкпАдминистрированиеКоннектора` есть; ключ продукта не генерируется

## Шлюз

- [ ] Не публикует 1С наружу: 1С только во внутренней сети / mTLS / VPN
- [ ] Тесты проходят без живой базы (мок слоя A)
- [ ] Покрытие `onecmcp` ≥ 90% (`./scripts/ci.sh`)
- [ ] MCP-инструменты discovery не выгружают всю конфигурацию целиком
- [ ] Сценарий «отгрузки за август по контрагенту» закрывается поиском + фильтром **или** отчётом `DemoSales` / типовым `Продажи`
- [ ] Пресет `guide` / `ONEC_PRESET` подсказывает типовые имена, не плодя MCP-tool на каждый документ
- [ ] Произвольный запрос без `ВЫБРАТЬ`/`SELECT` отвечает `400 query_rejected`
- [ ] `async: true` на query/report даёт `202` и `GET /v1/job/{id}` со статусом и результатом
- [ ] Запись без `confirm_token` — `400 confirm_required`; повтор `Idempotency-Key` не создаёт дубль
- [ ] `POST /v1/session/rollback` откатывает сессию агента
- [ ] `POST /v1/action` вне whitelist — не 200
- [ ] `GET /diag` не содержит токен; `product_license` = `not_required`
- [ ] Helm-чарт `deploy/helm/onecmcp` не содержит ключа продукта
- [ ] `GET /guide` отдаёт каталог; запись в плейбуке идёт через `data_dry_run`
- [ ] `serve` отдаёт MCP на `/mcp`; неизвестный `X-Tenant` — `404 unknown_tenant`
- [ ] превышение `RATE_LIMIT_PER_MINUTE` — `429 rate_limited`; `/health` не режется
- [ ] лимит суммы клиента — `400 limit_exceeded` на записи
- [ ] `GET /v1/audit` со скоупом `read` отдаёт только записи этого клиента; `created_refs` после записи
- [ ] `GET /v1/session/{id}` показывает операции сессии этого клиента; чужой `session_id` не откатывает чужие записи
- [ ] `GET /v1/job` отдаёт только задания этого клиента без `result`; чужой `job_id` на `GET /v1/job/{id}` — `404`
- [ ] веб-консоль `/` показывает REST и MCP; админка баз и операторов закрыта токеном/сессией; у полей настроек есть подсказка

## Репозиторий

- [ ] ADR добавлен, если менялась архитектура или контракт
- [ ] CI зелёный
- [ ] Документация внедренца: `docs/install.md` и `docs/usage.md` соответствуют фактическим командам и контракту
